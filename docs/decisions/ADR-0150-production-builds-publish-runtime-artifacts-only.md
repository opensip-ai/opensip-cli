# ADR-0150: Production builds publish runtime artifacts only

```yaml
id: ADR-0150
title: Production builds publish runtime artifacts only
date: 2026-07-11
status: active
supersedes: []
superseded_by: null
related: [ADR-0017, ADR-0009, ADR-0040]
tags: [packaging, build, release, testing]
enforcement: mechanizable
enforced-by: ['script:verify-published-artifacts', 'script:typecheck-tests', 'script:build-test-tsconfigs']
enforcement-reason: >
  verify-published-artifacts inspects both the real clean dist tree AND the actual
  `pnpm pack --dry-run --json` packlist for every release-order package and rejects
  any test/spec/fixture/coverage/hook path; typecheck-tests + build-test-tsconfigs
  keep the excluded test sources semantically checked in isolation. Both lanes run
  in PR/release/preflight.
```

**Decision:** The publish boundary is defined by two artifacts jointly, not by
config intent alone: (1) production `tsc` output, where every package's
`tsconfig.json` carries the canonical test/spec/fixture `exclude` set so builds
emit runtime bytes only; and (2) the actual `pnpm pack --dry-run --json` packlist,
verified before publish. Because the production build excludes tests, test
sources are semantically type-checked by a **separate, per-package no-emit test
project** (`<pkg>/tsconfig.test.json`, generated by `build-test-tsconfigs.mjs`)
composed into root `pnpm typecheck` via `typecheck-tests.mjs`. Packaging evidence
is valid only after a clean build; `verify-published-artifacts.mjs` scans the
contained built tree and the real packlist over `RELEASE_PACKAGE_ORDER`, rejects
publishable pack lifecycle hooks, and applies explicit resource/time bounds.

**Alternatives:**
- tsconfig `exclude` only — rejected: proves intent, not emitted/packed bytes; a
  bad `files` glob or a stray `.d.ts` still ships.
- npm `files`/`.npmignore` only — rejected: no semantic guarantee and easy to
  under-scope; does not observe the compiler's real emit.
- A single whole-repo "central" test project — rejected: one program spanning
  every package treats a type reached via a dependency's `dist/.d.ts` and via its
  `src` as two distinct nominal types (the monorepo dual-identity hazard) and
  activates cross-package module augmentations (graph/fitness/simulation augment
  core's `RunScope`), producing false positives in tests that legitimately compile
  a package in isolation. Per-package isolation matches how each package is built
  and run.

**Rationale:** Defense in depth: the compiler `exclude` prevents bad emit and the
packlist scan proves what each publishable package would actually ship — either
alone is bypassable. Vitest transpiles tests with esbuild and does NOT type-check,
so removing tests from production emit would silently drop their semantic checking;
the per-package `tsconfig.test.json` lane restores it without polluting the shipped
artifact. The pack scan costs one `pnpm pack --dry-run` per package (bounded by
`MAX_ENTRIES_PER_PACKAGE`, a pack timeout, and a max buffer); a publishable
manifest declaring `prepack`/`prepare`/`postpack` is rejected before any pnpm spawn.

**Consequences:**
- Every package `tsconfig.json` repeats the canonical `exclude` (TypeScript
  replaces, not merges, an inherited `exclude`); the **root** `tsconfig.json`
  stays exclude-free so typescript-eslint's `projectService` fallback still admits
  test files. `turbo.json` lists `tsconfig.json` as a global dependency so a
  config change busts the build cache.
- `pnpm verify:published-artifacts` runs in CI, release, and `release:preflight`
  after a clean build; a cached/incremental build is not valid packaging evidence.
- Test sources stay first-class: `pnpm typecheck` fails on a test-only type error
  via the generated per-package test projects, enforced in sync by
  `build-test-tsconfigs --check` in `pnpm lint`.

**Fitness check:** No check warranted — a source-only fitness check cannot observe
emitted or packed bytes; the release script (`verify-published-artifacts`) is the
direct invariant evaluator.
